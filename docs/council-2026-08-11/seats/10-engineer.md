THE ENGINEER'S AUDIT — Aurelius load-bearing structure, 2026-08-11

## 1. THE LOAD-BEARING AUDIT

**Scheduler.** Claims: named registry, Cole-retimable, once-per-day atomic claims, catch-up after downtime (`core/schedule.ts`, `core/catchUp.ts`). Actually guarantees: at-most-once daily execution *when the DB is reachable* — `claimDailyRun` deliberately runs **unclaimed** on claim-store failure (schedule.ts:85-86, "availability beats dedup"), so a DB flap re-opens the double-briefing window the claims were built to close. Bigger structural lie: the spine has **three parallel job lists** — `scheduleNamed` registrations in index.ts, `ONCE_PER_DAY` (schedule.ts:47-53), and catchUp's hardcoded `JOBS` (catchUp.ts:23-171). They have drifted: `retention_sweep`, `content_outcome`, and `training_trend_sweep` are registered and claimed (index.ts:1741-1766, schedule.ts:52) but **absent from catch-up** — a Mini asleep at 08:30 loses them silently, exactly the defect the catch-up file's own comment (line 152) says was fixed for the Sunday learners. `reachabilityAudit` rule 4 checks registration↔ONCE_PER_DAY but never registration↔catch-up, so the gate cannot see this.

**Tracing.** Claims "every decision visible" (trace.ts:3-8). Writes are fire-and-forget by design (trace.ts:49) and `traceOperatorId()` returning null silently drops all telemetry (trace.ts:31-33) — acceptable trade, honestly commented. The reassuring-direction lie is delivery: `morning_briefing` runs `generateMorningBriefing()` then `sendToCole()` (index.ts:1711-1716), but `sendToCole` **never throws** (telegram/bot.ts:210-227, returns false on failure). A Telegram outage yields: trace `status:"ok"`, JobRun `"done"` (no retry), and — worst — the Healthchecks dead-man ping **fires on trace ok, not on delivery** (trace.ts:130-132). The external monitor built to prove "the spine works" certifies a briefing Cole never received.

**Doctor** (core/doctor.ts, 912 lines). The strongest file in the repo — live probes, billing-vs-key discrimination, the vector-geometry check (458-503) and failover-share check (511-556) are genuinely second-operator-grade. Two honest gaps: it runs only when invoked (nothing schedules it; failover "runs for weeks unnoticed" is its own admission at 551), and its fix strings are still Railway-era on non-backup rows — "press Apply Changes in Railway" (94-95, 232) will be printed verbatim on the Mini; only `ephemeralHost()` (50-58) localizes the backup remedies.

**Backups** (core/backup.ts). Better than most hobby systems: pg_dump custom format, `pg_restore --list` TOC verification (62-64), mount-drop marker (48-50, though the `existsSync` re-check is nearly vacuous — writeFileSync throws first), failure → critical Bridge signal with once-per-day dedup (81-107). What "always-on" still lacks: no automated restore test (DEPLOY_MAC_MINI.md delegates monthly restore to Cole's memory), no offsite copy (NAS RAID1 is one house fire from zero), and the dump **contains OAuth refresh tokens and every credential row in plaintext** on an SMB share — hard rule 6 stops at the vector index.

**Budget alarm** (measurement/spend.ts). Honest ledger (null-not-zero, `estimated: true`), but its invoker is a rider on `queue_sweep` (index.ts:1850-1860): pause queue_sweep, lose the alarm. Prices are hand-maintained and self-declared unverified for every non-Anthropic provider (pricing.ts:33-39); the 2026-08-06 council already found the whole OpenAI failover tier pricing to null once (pricing.ts:74-81). A watchdog whose calibration drifts by design needs a scheduled recalibration ritual it doesn't have.

**Memory/embeddings.** The geometry-stranding failure mode is documented and doctored (doctor.ts:449-503) — good. But **nothing prunes LogEntry or ConversationTurn**: no `deleteMany` exists outside smoke/repair scripts. Every LLM call, trace, and slow request accretes forever into a table btree-indexed on a 1000-char message column (schema.prisma:124). Single-user scale buys years, not forever; "always-on" makes it a certainty, not a risk.

**Telegram.** Single long-poll loop with 10s retry (bot.ts:671); the doctor detects the second-poller 409 (769-779). It is simultaneously the failure-paging channel (trace.ts:159-166) — so the channel that reports outages is a single point of failure for hearing about outages, including its own.

**Two-process DB sharing.** The frontend imports ~30 backend modules directly (frontend/app/api/*), each Next route spinning the backend's PrismaClient against the same DB. Consequences: (a) two connection pools against Neon's free-tier cap; (b) migrations must land before either deploy or the frontend 500s on schema drift; (c) `autonomy/confirm/route.ts:8-18` **executes action finalizers inside the Next process** — real side effects (and their pageFailure/Telegram imports) run in a process whose env parity with the backend nothing checks; a frontend service without `TELEGRAM_BOT_TOKEN` finalizes silently. The rituals route (tuning/rituals/route.ts) is the honest counter-example — it detects the empty per-process registry and 409s. One route learned the lesson; the confirm route didn't.

## 3. THE MINI QUESTION

The migration plan (DEPLOY_MAC_MINI.md) is unusually good — launchd KeepAlive, sleep-off, local Postgres on SSD not NAS, pinned re-embed, the 7-day soak with a forced reboot. The code is *mostly* Mini-ready: `ephemeralHost()`, loopback-aware OAuth validation (doctor.ts:605-617), `AURELIUS_PUBLIC_URL`, and the watchdog (`process.exit(1)` + launchd is a correct pairing). What genuinely breaks or is unowned: (1) **SMB mount fragility** — launchd starts before Finder-login mounts; logs are pointed *at the NAS* (backend.log on /Volumes), so a dropped mount kills logging and backups together; (2) doctor fix-text still says Railway; (3) macOS auto-update reboots and the 26h watchdog blind window overlap — a wedge inside the first day of any boot is invisible (watchdog.ts:22-29); (4) no restore automation, no offsite; (5) secret handling: `.env` in plaintext plus unencrypted dumps holding tokens on the NAS; (6) Tailscale exposure is fine *only because* `AURELIUS_API_KEY` is mandatory — but `/intake` and `/l/:code` remain unauthenticated writes on any exposed origin. Verdict: Mini-ready for the soak; not yet ready to be trusted unattended for months.

## 4. THE JARVIS BILL

Voice-latency, always-listening presence is a different machine than this one. In order: (1) **Delivery-verified notification path first** — an operator you can't hear is not an operator; make send failure a job failure with retry, and ping Healthchecks only after confirmed delivery (~a day of work, buys the most trust per dollar). (2) **Watchdog-of-the-watchdog**: external synthetic probe (curl /health + a scheduled /doctor run posted somewhere Cole reads) — the current dead-man proves process-alive, the briefing ping proves spine-ran; neither proves *correct*. (3) **Latency budget**: the chat path today is routing + memory assembly + LLM + tool rounds — seconds. Voice needs <1.5s to first token: local STT (whisper.cpp, already on the roadmap), streamed responses (router doesn't stream today), Haiku-tier fast lane for acknowledgments, prompt cache kept warm (CACHE_BREAK already exists — the bones are right). (4) **Uptime**: UPS (already recommended), macOS update deferral, and a second cheap heartbeat host. (5) **Cost**: always-listening is dominated by STT (local = ~$0) and the fast conversational tier; the budget alarm must be verified against real bills before that volume arrives. Build 1-2 before any microphone: an always-on second operator is a promise about *being heard when it fails*, and that is the one promise the current bones don't yet keep.
